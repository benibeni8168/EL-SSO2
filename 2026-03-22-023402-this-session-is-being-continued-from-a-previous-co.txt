     Context

     PAM Integration — Implementation Plan

     Context

     The Teindi identity platform needs to integrate with Privileged Access
     Management (PAM) systems. No PAM support exists today. The integration must
      be vendor-agnostic (generic HTTP webhook, compatible with CyberArk,
     BeyondTrust, HashiCorp Vault, or any custom PAM API).

     Three behaviours are required:
     1. Step-up auth gate — when a user logs in to a "privileged" client,
     Keycloak calls the PAM webhook for approval before completing the login
     2. Session notification — when a privileged session is created or ended,
     Keycloak notifies the PAM system
     3. Config UI — admin settings page (Realm Settings → PAM tab) for full
     end-to-end configuration

     ---
     Architecture

     Login to privileged client
             │
             ▼
     PAM Check Authenticator ──POST /check──► PAM Webhook (CyberArk / Vault /
     custom)
             │                                        │
        allowed?──NO──► Deny login                   │
             │──YES──► Complete login                 │
                             │                        │
                    Session Created ──POST /session──► PAM Webhook (session
     notification)

     ---
     PAM Webhook API Contract (vendor-neutral)

     Check endpoint (POST {url}/check):
     Request:  { "userId", "username", "clientId", "realmId", "ipAddress",
     "timestamp" }
     Response: { "allowed": true, "reason": "...", "pamSessionRef": "..." }
     Session endpoint (POST {url}/session):
     Request:  { "event": "SESSION_CREATED"|"SESSION_ENDED", "sessionId",
     "userId", "username", "clientId", "realmId", "ipAddress", "timestamp" }
     Test endpoint (POST {url}/test): { "test": true } → 200 OK

     Auth: Authorization: {apiToken} header on all requests.

     Backend Implementation

     1. PAM SPI (server-spi-private/src/main/java/org/keycloak/pam/)

     New files:
     - PamProvider.java — interface with:
       - PamCheckResult checkAccess(String userId, String username, String 
     clientId, String realmId, String ipAddress)
       - void notifySession(String event, String sessionId, String userId, 
     String username, String clientId, String realmId, String ipAddress)
     - PamProviderFactory.java — extends ProviderFactory<PamProvider>
     - PamSpi.java — extends Spi (registers PamProvider class,
     PamProviderFactory class, name "pam")
     - PamCheckResult.java — POJO: { boolean allowed; String reason; String 
     pamSessionRef; }

     Register in server-spi-private/src/main/resources/META-INF/services/org.key
     cloak.provider.Spi

     2. Generic Webhook PAM Provider (services/src/main/java/org/keycloak/pam/)

     New files:
     - WebhookPamProvider.java — implements PamProvider:
       - On checkAccess(): POST JSON to {webhookUrl}/check with 5s timeout;
     parse { allowed, reason, pamSessionRef }
       - On notifySession(): POST JSON to {webhookUrl}/session (fire-and-forget
     async)
       - Uses java.net.http.HttpClient (same as LogExportEventListenerProvider)
     - WebhookPamProviderFactory.java — implements PamProviderFactory:
       - PROVIDER_ID = "webhook"
       - Reads config: webhookUrl, apiToken, privilegedClients
     (comma-separated), allClientsPrivileged, notifySessions,
     checkTimeoutSeconds
       - create(session) reads live config from realm attributes via
     PamConfigStore

     3. PAM Check Authenticator 
     (services/src/main/java/org/keycloak/authentication/authenticators/pam/)

     New files:
     - PamCheckAuthenticator.java — implements Authenticator:
       - authenticate(context):
           i. Get PamProvider from session
         ii. Check if current client is in the privileged list (or
     allClientsPrivileged)
         iii. If yes: call pamProvider.checkAccess(...)
         iv. If allowed=true: context.success()
         v. If allowed=false:
     context.failure(AuthenticationFlowError.ACCESS_DENIED) with error message
     from reason
         vi. If PAM is disabled or client is not privileged: context.success()
     - PamCheckAuthenticatorFactory.java — implements AuthenticatorFactory:
       - PROVIDER_ID = "pam-check"
       - Display name: "PAM Access Check"
       - Config properties: none (reads from realm-level PAM config)

     Register in services/src/main/resources/META-INF/services/org.keycloak.auth
     entication.AuthenticatorFactory

     4. PAM Session Event Listener 
     (services/src/main/java/org/keycloak/events/pam/)

     New files:
     - PamSessionEventListenerProvider.java — implements EventListenerProvider:
       - onEvent(Event event): If event type is LOGIN or LOGOUT, and PAM is
     enabled + notifySessions=true, call pamProvider.notifySession(...) (async,
     non-blocking)
       - onEvent(AdminEvent, boolean): no-op
     - PamSessionEventListenerProviderFactory.java — PROVIDER_ID = 
     "pam-session-notify"

     Register in services/src/main/resources/META-INF/services/org.keycloak.even

     - PamConfigStore.java — persists PamConfigRepresentation as JSON in realm

     - PamTestResultRepresentation.java — { sent: boolean, status: String,

  - PAM Check Authenticator — auth flow step that calls PAM before allowing
  login to privileged clients
  - Session Event Listener — notifies PAM on LOGIN and LOGOUT events
  - Admin REST API — GET/PUT /admin/realms/{realm}/pam for config, POST /test
  for connection testing

  - Session listener changed from global to per-realm (so the UI enable/disable
  actually works)
  - PAM denial reason no longer exposed to end users (shows standard "Access
  denied" page)
  - Corrupt PAM config now logs a warning instead of silently failing open
  - Test button disabled when form has unsaved changes

  How to use

  1. Go to Realm Settings → PAM tab
  2. Enable PAM, enter your PAM webhook URL and API token
  3. Add client IDs to the privileged clients list (or enable "All clients are
